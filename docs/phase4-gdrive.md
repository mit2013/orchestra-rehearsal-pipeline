# アマオケ練習録音 自動編集パイプライン ― フェーズ4: Google Driveアップロード

## 0. 位置づけ
フェーズ3(Boxアップロード)と並行する形で実装する。Google Driveには**WAVとMP3の両方**をアップロードする。

- WAV: 動画担当の動画担当向け。動画編集用の素材としての受け渡しなので、**ダウンロード制限は付けない**
- MP3: 団員の一部に「ダウンロード可能な音源」を個別共有したい場合の、Boxとは別の追加チャンネル。Box(団員全体向け、パスワード・ダウンロード不可)を置き換えるものではなく、必要な時だけ使う位置づけ

いずれもBoxのようなパスワード保護は行わない(Google Driveの共有機能にはパスワード保護の概念がないため、リンクを知っている人のみアクセス可能、という制御に留まる)。

**スコープ外(別指示書)**: Facebook Messengerへの通知文言生成。

## 1. 認証(OAuth 2.0)
- `.env`(gitignore対象)に以下を保存済み:
  - `GOOGLE_CLIENT_ID`
  - `GOOGLE_CLIENT_SECRET`
- Pythonの`google-auth-oauthlib`(`InstalledAppFlow`)を使う。デスクトップアプリ用のクライアントなので、Redirect URIの事前登録は不要
- 初回認証: `run_local_server(port=0)`(空いているポートを自動選択)でローカルサーバーを起動し、ブラウザでの認可を待つ → 完了後、トークンをローカルファイル(`.google_tokens.json`、**gitignore対象**)に保存する
- **Boxとの違いに注意**: Googleのリフレッシュトークンは通常ローテーションしない(同じ値を使い続けられる)。ただし、リフレッシュ時にアクセストークンを更新した場合は都度保存すること
- OAuth同意画面は既に「本番環境」ステータスに変更済み(テストのまま7日で失効する問題への対処は完了している)

## 2. スコープ
`https://www.googleapis.com/auth/drive.file`(このアプリが作成したファイルのみにアクセスする限定的なスコープ)

## 3. フォルダ構成(4階層、オーケストラ単位で分離)
```
orchestra-recording-pipeline/     ← 自動化専用のルートフォルダ(旧名: 練習録音)
  {orchestra}/                    ← 例: Windrose_Sinfonie_Orchester
    {date}/
      WAV/   ← WAVファイル
      MP3/   ← MP3ファイル
```
- Google Driveのルート直下に「orchestra-recording-pipeline」という名前のフォルダを探す。存在すれば再利用し、無ければ新規作成する。**このフォルダは自動化専用**であることが名前から分かるようにする(ユーザーが手動で作成した「練習録音」フォルダとは別物であり、`drive.file`スコープの制約上、手動作成フォルダはそもそもこのアプリからは見えないため、混同のリスクは実質ない)
- その中に、`{orchestra}`(その日付の`session_config.json`の`orchestra`値から、スペースをアンダースコアに置き換えて生成。例: `Windrose Sinfonie Orchester` → `Windrose_Sinfonie_Orchester`)という名前のフォルダを探す。存在すれば再利用し、無ければ新規作成する。**この値は`orchestra`設定から自動生成し、手入力・ハードコードしないこと**(表記揺れを防ぐため)
- その中に、日付名(例: `260802`)のフォルダを探す。存在すれば再利用し、無ければ新規作成する
- さらにその中に、`WAV`・`MP3`という名前のフォルダをそれぞれ探す。存在すれば再利用し、無ければ新規作成する
- いずれの階層も、再実行時に重複フォルダを作らないこと

### 移行(重要)
既存の260802は、旧構成(`練習録音/260802/{WAV,MP3}/`、旧ルート直下に直接日付フォルダがある状態)でアップロード済みである。以下の手順で新構成へ移行すること。

1. 旧ルートフォルダ(現在「練習録音」という名前で、このアプリが作成したもの)の**名前を`orchestra-recording-pipeline`に変更する**(リネームであり、フォルダIDは変わらない)
2. その直下に`{orchestra}`フォルダを作成する
3. 既存の`260802`フォルダ(`WAV`・`MP3`サブフォルダとその中身を含む)を、**フォルダごと**`{orchestra}`フォルダの子として移動する(個々のファイルを移動するのではなく、`260802`フォルダの`parents`を1回更新するだけでよい。中の`WAV`・`MP3`フォルダ・ファイルはすべて`260802`フォルダに付いてくる)

この移行により、`{date}`フォルダおよび`{date}/MP3`フォルダの**共有リンクURLは変わらない**(フォルダIDが不変のため)。前回共有したリンクは移行後もそのまま機能するはずなので、その通りになっているか確認すること。

## 4. アップロード対象とファイル名
### WAV
- 対象: `output/{date}/trimmed/{idx}_合奏{idx}_final.wav`(**ローカルにコピーを作らず、この既存ファイルを直接アップロード元とする**)
- アップロード先: `orchestra-recording-pipeline/{orchestra}/{date}/WAV/`
- アップロード先での表示名: `{date}_{タイトル}.wav`(タイトルはフェーズ2と同じ採番ルール: 2ブロック→前半/後半、3ブロック→前半/中盤/後半、それ以外→コマ1/コマ2...)

### MP3
- 対象: `output/{date}/export/*.mp3`(フェーズ2で作成済みのタグ付きMP3。Boxアップロードと同じソース)
- アップロード先: `orchestra-recording-pipeline/{orchestra}/{date}/MP3/`
- アップロード先での表示名: `export/`内のファイル名をそのまま使う(既に`{date}_{タイトル}.mp3`形式になっている)

### 共通: 変更なしファイルはアップロードをスキップする
帯域・ストレージの節約のため、以下の手順を必ず踏むこと。

1. アップロード対象と同名のファイルが、アップロード先に既に存在するか確認する
2. 存在する場合、Drive上のファイルメタデータから`md5Checksum`を取得する
3. ローカルファイルのMD5を計算し、`md5Checksum`と比較する
4. 一致すれば、**アップロードを行わずスキップする**(新しいバージョンも作らない)。ログに「スキップ(内容同一): {ファイル名}」のように明示すること
5. 不一致、またはDrive上に同名ファイルが存在しない場合のみ、実際にアップロードする(存在する場合は新しいバージョンとして)

- ローカルの`trimmed/`・`export/`配下は読み取り専用として扱い、変更・複製しないこと

## 5. 共有設定
共有リンクは**2種類**、それぞれ独立して設定する。

- **`{date}`フォルダ**(WAV・MP3両方を含む): 動画担当の動画担当へ渡す用。「リンクを知っている全員が閲覧者」(`type: anyone, role: reader`)、ダウンロード禁止しない
- **`{date}/MP3`フォルダ**: 団員の一部へダウンロード可能な音源として個別共有する用。同じく「リンクを知っている全員が閲覧者」、ダウンロード禁止しない

両方とも同じ設定内容(閲覧者・ダウンロード可)だが、**フォルダごとに明示的に共有リンクを設定すること**(親フォルダの設定が子フォルダへ継承される想定に頼らず、両方に個別設定する。継承の挙動に確信が持てないため、確実性を優先する)。

生成された2つの共有リンク(`{date}`フォルダ、`{date}/MP3`フォルダ)を、それぞれ分かりやすく出力すること(次フェーズの通知文言作成で使う)。

## 6. CLIコマンド
```bash
python pipeline.py gdrive-upload --date 260802
```

## 7. 検証してほしいこと
- WAV・MP3それぞれのアップロード後のファイル数が、その日付の合奏ブロック数と一致すること
- `orchestra-recording-pipeline`・`{orchestra}`・`{date}`・`WAV`・`MP3`の各フォルダが、再実行しても重複作成されないこと
- 260802の移行(旧ルートのリネーム、`{date}`フォルダごとの移動)が正しく行われ、ファイルIDが移行前後で変わっていないこと(再アップロードではなく移動であることの確認)
- 移行後も`{date}`フォルダ・`{date}/MP3`フォルダの共有リンクURLが移行前と同一で、実際に機能すること
- 同一内容のファイルを2回連続でアップロードした場合、2回目はスキップされ、新しいバージョンが作られないこと(ログにスキップである旨が出力されること)
- 内容を変更したファイル(例: タグだけ変えたMP3)を再実行した場合は、正しく新バージョンとしてアップロードされること
- `{date}`フォルダ・`{date}/MP3`フォルダそれぞれの共有権限を読み戻し、「リンクを知っている全員が閲覧者」・ダウンロード禁止されていないことを確認すること
