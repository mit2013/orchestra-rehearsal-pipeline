# アマオケ練習録音 自動編集パイプライン ― フェーズ5: 通知文言生成

## 0. 位置づけ
フェーズ1〜4(取り込み〜トリミング〜正規化・ミックス〜曲目エクスポート〜Box/Google Driveアップロード)が完了した状態から、最終フェーズとして実装する。

通知手段はFacebook Messengerでの手動送信から、**LINE Messaging APIによる自動送信へ移行する。** ただし段階的に導入し、**今回実装するのは(1)自分専用の完了通知のみ**とする。(2)動画担当を含むグループ、(3)一般団員グループへの自動送信は、グループIDの取得(Webhookを使った一度きりのブートストラップ作業)が別途必要なため、次のフェーズとして扱う。それまでは、下記①②③の文言を`messages.txt`から手動でコピーして送信する運用を継続する。

## 1. 生成する文言(2種類 + 任意1種類)

### ① 動画担当(動画担当)向け個別メッセージ
Google Driveの`{date}`フォルダ(WAV・MP3両方を含む)のリンクを使う。

```
{date}の練習録音です。
{Google Drive 日付フォルダのURL}

WAVとMP3が入っています。
```

### ② 団員グループ向けメッセージ
Boxの共有リンクとパスワードを使う。

```
{date}の練習録音をアップロードしました。
{Box共有リンクURL}
パスワード: {password}

※ストリーミング再生のみで、ダウンロードはできません。
```

### ③ (任意)ダウンロード可能版の個別共有用メッセージ
Google Driveの`{date}/MP3`フォルダのリンクを使う。**通常の運用では使わず、必要な団員にだけ個別送信する想定**のものなので、出力時に「任意・通常は送らない」旨が一目で分かるようラベルを付けること。

```
{date}の練習録音(ダウンロード可能版)です。
{Google Drive MP3フォルダのURL}
```

## 2. リンク・パスワードの取得方法
**ローカルにリンクをキャッシュするファイルを新設しないこと。** 実行のたびに、Box・Google Drive双方のAPIへ問い合わせて最新のリンクを取得する(box-upload/gdrive-uploadで既に実装済みのフォルダ探索ロジックを再利用してよい)。

- Box: `{date}`フォルダの共有リンクURLをAPIから取得する。パスワードはAPIから取得せず(セキュリティ上、Box APIはパスワードを返却しない)、`{concert_date}{password_suffix}`の式からこの場でローカル計算する
- Google Drive: `{date}`フォルダ、`{date}/MP3`フォルダそれぞれのURLをAPIから取得する(フォルダIDから`https://drive.google.com/drive/folders/{folder_id}`の形式で構成できる)

## 3. 出力
- 標準出力に、①②③それぞれラベル付きで分かりやすく表示する
- あわせて`output/{date}/messages.txt`にも保存する(コピー&ペーストしやすいように)
- **さらに、①②③をまとめた内容を、LINE経由で自分宛にpush通知する**(下記§3.1参照)

### 3.1 LINE通知(自分専用)
- `.env`(gitignore対象)に以下を保存済み:
  - `LINE_CHANNEL_ACCESS_TOKEN`(長期チャネルアクセストークン)
  - `LINE_MY_USER_ID`(自分のLINEユーザーID、`U`で始まる文字列)
- エンドポイント: `https://api.line.me/v2/bot/message/push`(**`https://line.me`ではないので注意**)
- リクエスト: `POST`、ヘッダーに`Authorization: Bearer {LINE_CHANNEL_ACCESS_TOKEN}`と`Content-Type: application/json`
- ボディ:
```json
{
  "to": "{LINE_MY_USER_ID}",
  "messages": [
    {"type": "text", "text": "{date}の練習録音、パイプライン完了しました。\n\n{①②③の内容}"}
  ]
}
```
- LINEのテキストメッセージは十分な文字数を扱えるため、①②③をそのまま1メッセージにまとめてよい
- 送信に失敗しても(ネットワークエラー、トークン未設定等)、標準出力・`messages.txt`への出力自体は完了させること(LINE通知は付加的な機能であり、失敗しても本体機能を止めない)。失敗時はその旨を標準出力にログすること

## 4. CLIコマンド
```bash
python pipeline.py notify --date 260802
```

## 5. 検証してほしいこと
- 生成された3つの文言に、正しい日付・URL・パスワードが入っていること
- Boxのパスワードが、API経由ではなくローカルの計算式(`{concert_date}{password_suffix}`)から生成されていること
- 260802・260726両方で実行し、それぞれ正しいリンクが埋め込まれること
- `output/{date}/messages.txt`が正しく生成されること
- ③(任意版)が、①②と明確に区別されたラベル付きで出力されていること
- **実際にLINEへpush通知が届くこと**(スマホのLINEアプリで、友だち追加した公式アカウントからメッセージが届くことを目視確認する。API上の成功レスポンスだけでなく、人間の目での確認が必要)
- `LINE_CHANNEL_ACCESS_TOKEN`が未設定の場合に、エラーで止まらず標準出力への出力は完了すること(§3.1の失敗時の挙動確認)
