# アマオケ練習録音パイプライン ― 研究ブランチ: ダイジェスト版の設計見直し(ステージG)

## 0. ブランチの厳守(重要)
作業は必ず`research/fine-segmentation`ブランチで行うこと。**現在`feature/tuning-precision`
ブランチでの作業(mainへの還元)が別途存在する**ため、作業開始前に必ず
`git branch --show-current`で現在のブランチを確認し、`research/fine-segmentation`で
なければ`git checkout research/fine-segmentation`してから始めること。`main`・
`feature/tuning-precision`のいずれにも一切コミットしないこと。作業完了時にも再度
ブランチを確認し、報告に含めること。

## 1. 位置づけ
既存の4値分類(silence/tuning/speech/playing)は、「無音・チューニング・発言を確定し、
残りをplayingとする」消去法の設計になっており、これがダイジェストの圧縮率が低い
(実測8割程度、体感の演奏比率3〜5割と乖離)主因と判断されている。本ステージでは、
playingを積極的な証拠で判定する設計に見直す。対象は引き続き260802合奏2のみとする
(パイロット)。

## 2. 設計方針の転換(重要、必ず踏まえること)
これまでの本編トリミング(音出し・休憩の除去)は「演奏を削るより多めに残す」安全側
バイアスが正しかった。理由は、トリミング後のファイルが唯一の成果物であり、削りすぎが
取り返しのつかない損失になるためである。

**ダイジェストはこれとは性質が異なる。** ダイジェストは`trimmed/`という完全な音源が
別途保存されている前提の、要約・利便性のための派生物である。したがって:

- 演奏を多少削りすぎても実害は小さい(元の完全版が別途ある)
- 逆に、発言・雑音を残しすぎるとダイジェストとして機能しない(今回の問題そのもの)

**この2点により、ダイジェストのplaying判定は「怪しければ除外する」方向に倒すこと。**
これはこれまでの安全側バイアスの単純な踏襲ではなく、意図的な逆転であることを認識して
設計すること。

## 3. ステージG-1: 診断 ― 演奏を特徴づける音響的な違いを実測する
これまでのチューニング検出改良と同じく、決め打ちで設計せず、実測してから設計すること。

### G-1-1. 参照区間の選定
以下の2段階で参照区間(「明らかに演奏している」「明らかに演奏していない」)を集める:

1. **機械的な抽出(人手不要)**: 既存の`states.json`・波形から、極端に分かりやすい区間を
   自動抽出する。目安: 10秒以上RMSが高く持続する区間(演奏の可能性が高い)、5秒以上
   ほぼ無音の区間(非演奏の可能性が高い)。これらを「確度の高い参照データ」の初期セットと
   する
2. **人手での追加(紛らわしい例)**: F-2で既に出力済みの3枚の波形画像を踏まえ、
   「一見演奏に見えるが実は発言/雑音かもしれない」「一見静かだが実は弱奏かもしれない」
   区間の候補があれば、人間に確認を求めてよい(この確認は例外的にYes/No/入力待ちを
   行ってよい箇所とする)。ただし1で十分な参照データ(目安30件以上)が集まるなら、
   2は省略してよい

### G-1-2. 候補特徴量の実測比較
以下を参照区間ごとに算出し、演奏/非演奏をどれだけ分離できるか比較する:
- 多声性(polyphony): 同時に存在する基本周波数・倍音系列の数の推定
- 調和性/雑音比: 音程のある音か雑然とした音か
- スペクトルの短時間安定性: 発話は音色が目まぐるしく変わるが、演奏はより安定していると
  想定される
- オンセット(音の立ち上がり)密度

### G-1-3. 既製モデルとの比較(可能であれば)
軽量な汎用音声分類モデル(例: YAMNet、AudioSetで学習済み)を追加の依存関係として
試してよい。同じ参照区間に対する分類結果を、上記の手作り特徴量と比較する。
**インストールや実行環境の問題で動かせない場合は無理に対応せず、手作り特徴量のみで
進めてよい**(迷ったらこうする: 諦めて手作り特徴量だけで進める)。

### G-1-4. 報告
どの特徴量(または組み合わせ)が最も演奏/非演奏を分離できたか、実測値とともに報告する。

## 4. ステージG-2: 分類の再設計
G-1の結果に基づき、silence/tuning/speech/playingの各クラスを、それぞれ積極的な証拠で
判定する方式に置き換える。「残りはplaying」という消去法をやめること。

具体的な実装方式はG-1の結果次第で決めてよい(迷ったらこうする: G-1で最も分離性能が
高かった特徴量を主判定に据え、他の特徴量は補助として使う)。分類を確信度スコアとして
出力し、ダイジェスト生成側で閾値を適用する設計(分類そのものと、ダイジェスト用の
閾値判断を分離する)を推奨するが、必須ではない。

§2の方針(怪しければ除外する)を、この再設計に反映すること。

## 5. ステージG-3: 比較評価
- F-2と同じ形式(10分ごとの波形+スペクトログラム+ラベル帯)の画像を、新しい分類結果で
  再生成し、旧版と並べて比較できるようにする
- F-1・F-3で構築したレビュー基盤(候補抽出・クリップ生成・CSV)を再利用し、
  同じ参照点に対して旧分類・新分類それぞれの正誤を比較する
- 新しいダイジェストを生成し、圧縮率が体感の演奏比率(3〜5割)に近づいたか報告する
- 結合点のクリックノイズがないことも、これまでと同様に確認する
